# Design System: Mariana Torres GitHub Profile

## Overview

**Creative North Star: "The supplied raspberry-garden cover"**

The supplied Hello Kitty coding cover in a raspberry garden is the visual authority. The README carries its cream, raspberry, forest and olive colors into flat pixel illustrations, stepped badges, cassette artwork and a gingham footer. The cover stays first and unchanged.

This is a GitHub profile README. Its readable content, headings, disclosures, links, wrapping, background and interaction states belong to GitHub’s native renderer. Custom typography and decoration live inside local SVG assets generated by build_assets.py.

**Key Characteristics:**

- User-pinned cover and recurring raspberry pixel motif.
- Cream-backed artwork with raspberry, forest and olive accents.
- Serif SVG titles paired with sans-serif SVG labels and native GitHub prose.
- Single reading flow with inline assets and native disclosures.

**The Cover Rule.** Keep assets/capa.gif first and byte-for-byte unchanged.

## Colors

The SVG palette uses warm cream against raspberry lettering, forest and olive accents, and small rose details. Values in the frontmatter come from `build_assets.py` and the stats URLs in `README.md`.

- **Primary:** raspberry titles, LinkedIn/repository links, development labels and Laufey cassette.
- **Secondary:** forest Instagram/data labels and Billie Eilish cassette; olive Spotify/design labels, leaves and cassette underlines; infrastructure plum for infrastructure labels.
- **Detail:** rose divider lines, gingham squares and intro flower; berry and berry-highlight pixel fruit; flower-gold center pixels. Stats-olive is the separate icon color in the external stats URL.
- **Neutral:** cream SVG backing and light label text; ink text in the external stats requests. GitHub owns the surrounding page and Markdown text colors.

**The Backing Rule.** Keep cream backing inside introduction, project-title and footer SVGs so their raspberry lettering does not depend on GitHub’s page background.

## Typography

The frontmatter records SVG user-unit sizes at each asset’s intrinsic scale. The serif stack gives the greeting, project titles, cassette titles and footer their character; the sans-serif stack supplies badge and cassette-detail labels. The SVG generator specifies no font weights, line-height scale or letter spacing.

Markdown headings, body text, bold, italics, `<sub>` captions and `<summary>` disclosures use GitHub’s native typography. Asset resizing also scales its embedded text: project title widths in the README differ from intrinsic SVG widths for the longer titles.

**The Platform Rule.** Let GitHub own body typography, background, responsive wrapping, focus and disclosure behavior.

## Layout

`README.md` is one native reading column. The cover, greeting and social links are centered; biography, skills, projects and contact text follow native Markdown flow. Music assets and activity graphics are centered. Inline badges and cassettes wrap naturally without a locally defined breakpoint or grid.

The cover, divider and footer request full available width. The greeting requests (520px); social links use height (32px); technology labels use height (28px); cassettes request width (302px). Project labels request widths (126px), (372px), (128px) and (352px), while their source SVGs are respectively (126px), (420px), (128px) and (402px) wide. Their source height is (42px).

Vertical separation uses native paragraphs/headings plus explicit `<br />` and paired `<br />` elements. There is no custom page spacing scale. Divider artwork uses a (1000 × 28) viewBox, footer artwork a (1000 × 66) viewBox. The cover’s encoded image is (1024 × 341).

The English biography, extended study map and activity graphics use native `<details>` disclosures. External stats request widths (420px) and (320px); the contribution snake requests full width and selects its dark SVG through `<picture>`.

## Elevation & Depth

Local artwork is flat. Solid color blocks, pixel silhouettes and cream inset areas provide separation; the SVG generator defines no shadows, gradients, blur or depth effects.

## Shapes

Badges and cassette edges use stepped rectangular silhouettes, not rounded CSS corners. Social links use (4px) corner steps; technology labels use (2px) steps. Raspberry sprites use a default (2px) pixel unit and `shape-rendering="crispEdges"`. The footer’s gingham uses (8px) squares across a (16px) strip. Cassette reels use circles inside the otherwise rectangular illustration.

## Do's and Don'ts

- Do regenerate local SVG artwork through build_assets.py.
- Do retain meaningful image alt text and empty alt text for decorative dividers.
- Do keep the supplied cover and the existing social destinations.
- Do preserve cream backing for project labels and the footer.
- Don’t introduce a custom app shell, CSS breakpoint system or custom GitHub body font.
- Don’t invent hover treatments, font weights, spacing scales or animation timing that the README does not define.
- Don’t claim the local layout plates are browser screenshots or proof of live GitHub rendering.
- Do preserve the real 50-frame GIF in assets/capa.gif; the reattached file had been flattened to PNG and was replaced with the visually identical original animation.
